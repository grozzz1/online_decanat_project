# Визуальный анализ документов

Обработка JPG/PNG и PDF подключена к сайту и Telegram-боту. Алгоритм ищет
**визуальные кандидаты** печати и подписи. Он не проверяет подлинность, личность
подписанта, юридическую силу или правильность заполнения документа.

## Запуск на Windows

Из корня проекта, тем же Python, которым запускается приложение:

```powershell
python -m pip install -r requirements.txt
python main.py
```

Для OCR нужен отдельно установленный Tesseract с `rus.traineddata`,
`eng.traineddata` и желательно `osd.traineddata`. Пример `.env`:

```dotenv
TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe
```

Настройки `BOT_TOKEN`, `DEAN_CHAT_ID`, `ADMIN_LOG_CHAT_ID` остаются прежними.
Вход на сайт http://localhost:5000 осуществляется по ссылке из команды `/start`
боту на том же компьютере. Telegram API должен быть доступен из Python.
Если в окружении установлен другой пакет OpenCV, используйте отдельное `.venv`:
пакеты `opencv-python` и `opencv-python-headless` предоставляют один модуль `cv2`.

Можно отправлять один JPG, PNG или PDF до 10 МБ. PDF — от 1 до 12 страниц;
изображения — до 20 мегапикселей. В Telegram доступны как фотографии,
так и вложения JPG/PNG/PDF. Для вопроса по документу нужен вопрос в подписи
к вложению. PDF передаётся деканату исходным файлом, изображения — фотографией.

## Пайплайн и API

1. `utils/documents.py` проверяет содержимое, декодирует изображения с учётом
   EXIF и прозрачности; PDF рендерится PDFium, до 150 dpi и 2000 пикселей
   по длинной стороне. PDFium защищён общим блокировщиком, поскольку библиотека
   не рассчитана на одновременные вызовы из нескольких потоков.
2. `utils/ocr.py` пытается исправить ориентацию на 90/180/270 градусов через
   Tesseract OSD при достаточной оценке уверенности. Без OSD обработка продолжается.
   Существующий OCR `image_to_string(..., --psm 6)` сохранён. Отдельный
   `image_to_data(..., --psm 11)` возвращает слова, координаты и строки текста.
3. `utils/document_cv.py` анализирует копию страницы. Преобразования для CV
   не передаются в OCR. Работа выполняется через `asyncio.to_thread`.
4. `utils/validation.py` получает результаты анализа. В существующем проекте
   теперь используется предоставленное вымышленное `rules.md`: предварительная
   комплектность возвращается в `validation.completeness` с источниками правил.
   Сомнительный CV остаётся неизвестным и не подтверждает подлинность. Извлечение полей трёх типов
   и проверки их согласованности описаны в [DOCUMENT_FIELDS.md](DOCUMENT_FIELDS.md).
5. Сайт сохраняет результаты в памяти `WebStore`, отдаёт их в существующем
   `/api/messages` и показывает в просмотрщике. Деканат получает оригинал,
   распознанный текст и текстовое описание результатов. Пользователь Telegram
   также получает описание найденных признаков.

Независимый интерфейс для одной PIL-страницы:

```python
from PIL import Image
from utils.document_cv import analyze_document_visuals

with Image.open("document.png") as image:
    result = analyze_document_visuals(image, ocr_words=[], page=1)
```

Без OCR подпись получает роль `unknown`. Для всего файла:

```python
from io import BytesIO
from pathlib import Path
from utils.ocr import analyze_document

result = analyze_document(BytesIO(Path("document.pdf").read_bytes()))
# recognized: текст; visuals: JSON-совместимые результаты;
# validation: информационная проверка; previews: JPEG-байты страниц (внутреннее поле).
```

`recognize_text()` / `recognize_text_async()` продолжают возвращать строку.
Поле формы `photo` и адрес `/api/requests/<id>/photo` сохранены; последний
возвращает исходный файл, в том числе PDF. Новый защищённый маршрут
`/api/requests/<id>/pages/<page>/photo` возвращает JPEG страницы. Чужие документы
недоступны. Существующие проверки сессии, CSRF и размера загрузки сохранены.

## Координаты и формат

`bbox=[x1,y1,x2,y2]`, начало координат — левый верхний угол, правая и нижняя
границы исключающие. `page` нумеруется с 1. Координаты относятся к странице
**после EXIF/OSD**, размеры которой находятся в `pages`. Для PDF это рендер
страницы, а не координаты в PDF-пунктах. Внутреннее уменьшение для CV до
1600 пикселей пересчитывается обратно в эту систему координат.
Предпросмотр имеет те же размеры и ориентацию, поэтому canvas рисует рамки
пропорционально отображаемым размерам изображения, включая zoom и смену страницы.

```json
{
  "stamp": {"detected": false, "bbox": null, "confidence": 0.0, "page": null, "status": "not_detected"},
  "student_signature": {"detected": false, "bbox": null, "confidence": 0.0, "page": null, "status": "unknown"},
  "signature": {"detected": true, "type": "signature", "role": "unknown", "role_status": "unknown", "bbox": [110, 790, 285, 845], "confidence": 0.55, "page": 1, "status": "uncertain"},
  "detections": [
    {"detected": true, "type": "signature", "role": "unknown", "role_status": "unknown", "bbox": [110, 790, 285, 845], "confidence": 0.55, "page": 1, "status": "uncertain", "evidence": {}}
  ],
  "pages": [{"page": 1, "width": 800, "height": 1100, "analysis_status": "complete"}],
  "warnings": [],
  "score_kind": "heuristic_v1",
  "authenticity_verified": false
}
```

Это пример формы полей; в реальном результате обнаруженные объекты также
находятся в `detections`, а `stamp`, `signature`, `student_signature` содержат
лучший соответствующий кандидат. Каждый кандидат содержит численные признаки
в `evidence`. `pages[].ocr_words` содержит текст, `bbox`, OCR-confidence и ID строки;
этот формат можно использовать для будущей подсветки текстовых полей.

`detected=true` означает наличие кандидата выше порога, включая сомнительные.
`status=uncertain` означает score ниже 0.70. При отсутствии подходящего кандидата
возвращаются `detected=false`, `bbox=null`. Если подпись найдена, но роль неизвестна,
`student_signature.status=unknown`; `role=student` означает лишь близкий текстовый
контекст. Ошибка CV тоже приводит к статусу `unknown` для не найденных элементов,
а не к утверждению об их отсутствии. Она не мешает пересылке документа с успешным OCR.

## Алгоритмы и прозрачные scores

Печать:

- HSV-маска синих/фиолетовых оттенков и дополнительная маска других насыщенных цветов.
- CLAHE, лёгкое Gaussian-размытие, адаптивная бинаризация для монохромного поиска.
- Морфологическое замыкание, внешние контуры, относительные ограничения размера,
  соотношения сторон, circularity `4*pi*area/perimeter²`, качество аппроксимации эллипсом.
- Плотность внутренних штрихов, отсечение сплошных пятен. HoughCircles предлагает
  запасные круги; проверяются покрытие кольца, радиальное направление границ и внутренний текст.
- Пересекающиеся кандидаты объединяются отдельно по типам. Максимум 40 кандидатов каждого типа на страницу.

Score контура: `0.20 + 0.18*circularity + 0.18*ellipse_fit +
0.18*min(1, interior_ink/0.08) + colour_bonus`. Цветовой бонус 0.13 для
синих/фиолетовых и 0.07 для остальных цветов, для монохромного контура — 0.
Без внутренних штрихов score ограничен 0.55. Hough: `0.43 + 0.15*ring_coverage`,
поэтому такой запасной кандидат всегда сомнительный.

Подпись:

- Удаление длинных горизонтальных/вертикальных линий бланка с локальным восстановлением
  пересечений штрихов. Вся пустая линия при этом обратно не добавляется.
  Удаление печатных OCR-слов и областей печатей; OCR-фрагмент сохраняется, если
  пересекающий его нерегулярный связный штрих заметно выходит за границы слова
  и находится у ориентира подписи.
- Дилатация соединяет близкие штрихи на всей странице **до** проверки областей
  интереса. Рамка строится по объединённым исходным пикселям, а не по расширенной
  маске; добавляется небольшой отступ относительно размера страницы.
  Это исправляет прежнее обрезание по ROI: частичная рамка могла выигрывать
  дедупликацию у полной. Размеры ядер, областей и отступов относительные.
- Контуры и связные компоненты: относительный размер, вытянутость, плотность штрихов,
  доля самой широкой связной компоненты, вариация высот и заполнение строк области.
  Регулярные раздельные печатные символы и остатки линий отбрасываются.
- Поиск около OCR-ориентиров «Подпись студента», «Подпись заявителя», «Подпись»,
  «Студент», «Заявитель», в том числе с небольшими OCR-ошибками. Размеры областей
  зависят от страницы и высоты текста. Дополнительный поиск — в нижней части страницы.
- Роль `student` присваивается только по сочетанию подписи и студента/заявителя
  в близком текстовом контексте. Ориентир сотрудника, общий «Дата / Подпись» или
  противоречивый контекст не устанавливают роль студента.
- Явный ориентир «Образец подписи» не подтверждает подпись студента.
  Кандидат, касающийся края страницы, остаётся сомнительным: полную границу
  по обрезанному изображению восстановить нельзя.

Score подписи: `0.25 + 0.20*connected_width + 0.10*min(1,height_variation) +
0.10*occupied_rows + context_bonus`. Бонус контекста — 0.18. Без текстового ориентира
score ограничен 0.60. Общий минимальный score — 0.42, верхний предел — 0.95.
Это воспроизводимые эвристические оценки, **не вероятности** и не показатели точности.

Зелёные рамки — печати, синие — подписи, жёлтые — сомнительные кандидаты.
Переключатель подсветки, выбор страницы PDF и ссылка на оригинал находятся
в существующем просмотрщике. Выбор нового файла очищает старые рамки.

## Отладка

Для анализа отдельного файла и сохранения PNG с рамками:

```powershell
python -m utils.ocr document.pdf --debug-dir .tmp/cv-debug --output .tmp/result.json
```

Для документов, загружаемых через сайт/бота, можно добавить в `.env`:

```dotenv
DOCUMENT_CV_DEBUG_DIR=.tmp/cv-debug
```

После перезапуска туда сохраняются изображения каждой обработанной страницы
с уникальным префиксом. По умолчанию сохранение выключено. Файлы содержат
документы пользователя; удаляйте ненужные отладочные копии. `.tmp` исключена из Git.

## Проверки

Основные тесты используют стандартный `unittest`:

```powershell
python -m unittest discover -s tests -v
```

Регрессионные сценарии: печать и подпись вместе, каждый объект отдельно,
обычный печатный текст и линии без объектов, несколько подписей, подпись сотрудника,
отсутствие OCR-контекста, монохромный скан, умеренный шум, поворот на 7°,
OSD-коррекция на 90° (с подставленным ответом OSD), увеличение разрешения,
разные цвета и овальная печать, OCR-ошибка ориентира, PNG отладки,
двухстраничный PDF, ошибки CV, ограничения файлов/страниц, прозрачность/EXIF,
загрузка/пересылка через Flask и обработчик Telegram, доступ к страницам и CSRF.
OCR в регрессионных и интеграционных тестах подставляется для воспроизводимости.
Тестовые документы синтетические, Telegram-запросы заменены mock-объектами.

Дополнительно выполнен локальный запуск **настоящего Tesseract** на синтетическом
документе с русским ориентиром: получены OCR-текст, печать и подпись с ролью `student`.
Проверка OSD на этом примере не установила ориентацию, что отражено в `warnings`.

Необязательная браузерная проверка (требует установленный Google Chrome):

```powershell
python -m pip install -r requirements-dev.txt
$env:PYTHONPATH = "$PWD"
python tests/browser_visuals.py
```

Она поднимает отдельный локальный сервер с подставленным Telegram, проверяет
страницы PDF, повторное открытие документа из чата, цвета canvas, масштабирование,
узкий экран, выключение подсветки и сброс старых рамок. Снимок — `.tmp/cv-viewer.png`.
Тестовый шрифт — Arial из Windows, поэтому текущие фикстуры рассчитаны на Windows.

## Ограничения

- На реальных студенческих документах precision/recall **не измерены**.
  Нужна размеченная выборка с разнообразными бланками, сканами и почерками.
- Классический OpenCV не отличает надёжно подпись от похожего рукописного слова,
  завитка или логотипа. Слабые признаки остаются сомнительными кандидатами,
  а роль без OCR-контекста — неизвестной.
- Печати, фотографии/логотипы круглой формы, текст на кривой и сложные фоны могут
  давать ложные кандидаты. Бледные, частичные печати могут быть пропущены.
- Удаление OCR-слов может скрыть подпись, которую OCR уверенно принял за текст.
  Подписи, перекрывающиеся с печатью, могут быть пропущены при маскировании печати.
- OSD требует достаточно текста. Повороты на 90/180/270° исправляются только
  при уверенном результате OSD; перспективная коррекция не реализована.
  Небольшой наклон проверен синтетически, сильный наклон ухудшает поиск подписи.
- На странице без текстового ориентира общий поиск подписей ограничен нижней частью.
- Дополнительные вызовы Tesseract увеличивают время обработки, особенно PDF.
  Нейросети и платные API не используются.
- Исходное хранилище проекта остаётся в памяти: результаты, история и сессии
  теряются при перезапуске; постоянная БД не добавлялась.
