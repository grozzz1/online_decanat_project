# Локальный AI-пайплайн

Tesseract и прежний Regex остаются первым этапом. Qwen3-4B-Instruct-2507 Q4_K_M
восстанавливает только отсутствующие/некорректные текстовые поля. Подписи и печати
остаются результатом OpenCV. При недоступности модели Regex, CV и детерминированные
ответы продолжают работать. Эталонные ответы не используются при обработке.

## Установка и запуск в Windows

Из корня проекта, PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts/setup_local_ai.py
.\.venv\Scripts\python.exe scripts/start_local_ai.py
```

Последняя команда занимает терминал. В другом терминале:

```powershell
.\.venv\Scripts\python.exe main.py
```

Сайт: http://localhost:5000. Авторизация через существующего Telegram-бота сохранена.
AI работает через `127.0.0.1:18081`. Никаких облачных AI API не используется;
существующая отправка обращения в Telegram-деканат сохранена.

Для поддерживаемой видеокарты можно установить Vulkan-сборку и запустить её:

```powershell
.\.venv\Scripts\python.exe scripts/setup_local_ai.py --gpu
.\.venv\Scripts\python.exe scripts/start_local_ai.py --gpu
```

Сначала остановите предыдущий сервер через Ctrl+C. Скрипт проверяет уже работающий
сервер и не запускает вторую копию модели. По умолчанию используется CPU, 4 потока;
число потоков можно изменить через `--threads`. Выбранный backend и команда запуска
записываются в `.local_ai/runtime.json`. Поддержка GPU зависит от драйвера и памяти.

Установщик закреплён на llama.cpp `b11429` и конкретной ревизии квантованной
[Qwen3-4B-Instruct-2507 от Unsloth](https://huggingface.co/unsloth/Qwen3-4B-Instruct-2507-GGUF/tree/a06e946bb6b655725eafa393f4a9745d460374c9).
Это явно указанная instruction-версия Qwen3-4B, без подмены другой моделью.
GGUF проверяется по SHA256 из метаданных выбранной ревизии. Модель занимает около
2.5 ГБ; веса и переносные бинарные файлы исключены из Git. Манифест установки —
`models/installation.json`. В [llama.cpp server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)
используются ограничение контекста, один слот, JSON Schema и отключённые рассуждения.

Температура — 0, seed — 42; `/no_think`, `--reasoning off` и
`chat_template_kwargs.enable_thinking=false`. Сервер держит модель загруженной
между запросами. Параметры клиента настраиваются через `.env`; образец без секретов —
[.env.example](../.env.example). `LOCAL_AI_ENABLED=0` выключает генерацию.
HTTP-клиент разрешает только loopback, не использует системный прокси и не следует
перенаправлениям. Промпты, OCR и данные документов не отправляются на сайты загрузки моделей.

## Как устроено извлечение

Если все текстовые поля корректно найдены, Qwen не вызывается. Иначе ей передаются
исходный OCR, тип, имена отсутствующих полей и уже найденные текстовые значения.
Ответ ограничен запрошенными ключами. Для нового значения обязательна точная
цитата с контекстом поля; JSON null означает, что значение не найдено.

Программная проверка контролирует тип, существование и роль даты, соответствие
периода, буквальное присутствие значения/цитаты в OCR, неоднозначность и конфликт
с подтверждёнными данными. Значения из отрицательного/неопределённого контекста
консервативно отклоняются. Подтверждённые Regex-поля не заменяются. При изменении
выбранного типа используются сохранённые OCR/CV; анализ той же схемы переиспользуется.
Подтверждение расхождения типов по-прежнему не означает принятия документа.

Для каждого поля сохраняются `field_sources`: `regex`, `qwen`, `cv`, `missing`
или `unknown`; для восстановленного поля — `field_evidence.quote`.
В интерфейсе это показано как «из текста», «уточнено AI по цитате» или
«визуальный анализ». Непроверенные предложения модели остаются только в приватном
результате обработки для диагностики, а не в итоговых полях.

## Вопросы и RAG

Единый `QuestionEngine` используется сайтом, ботом и бенчмарком:

- значения полей, наличие/отсутствие отметок и комплектность определяются Python;
- типовые вопросы о требованиях и окончательном решении получают проверяемые пункты правил;
- BM25 ищет другие подходящие пункты локально;
- для сложного вопроса Qwen выбирает подтверждающие факты, после чего код проверяет
  источники, полные цитаты и релевантность; пользователю показываются проверенные цитаты;
- при нехватке данных, ошибке источников или недоступности модели формируется отказ.

Свободные объяснения LLM не передаются пользователю как проверенный факт. Для сложных
вопросов это намеренно ограничивает выразительность: система сопоставляет поля и
цитаты, но не выносит решения о праве на отпуск или принятии документа. Нельзя
универсально доказать правильность свободного текста одной проверкой JSON.

Ответ совместим с форматом оценщика: `question_id`, `answerable`, `value`, `answer`,
`sources`. Неизвестное значение — настоящий JSON null. Технический сбой не выдаётся
за доказанное отсутствие информации. После невалидного/неподтверждённого ответа
допускается одна повторная генерация. Есть счётчики отклонений, исправлений и отказов.

В веб-просмотрщике есть поле «Вопрос AI-помощнику по этому документу».
`POST /api/requests/<id>/ask` возвращает 202; результат и `ai_status` приходят через
существующий `/api/messages`. Сохраняются сессия, CSRF и проверка владельца.
Инференс идёт в фоне через `asyncio.to_thread`, с ограничением параллельности и тайм-аутами.
Вопрос в подписи к документу также получает AI-ответ. В Telegram можно задать вопрос
о последнем документе через обычный пункт меню; контекст изолирован по чату/пользователю,
ограничен 256 записями и хранится в памяти один час.

`rules.md` разбивается по пунктам, например `rule:1.3`; сохраняются текст, заголовок,
путь и SHA256. Индекс `.local_ai/knowledge.json` переиспользуется и обновляется при
изменении файлов. Дополнительные Markdown/TXT и PDF с текстовым слоем задаются
через `KNOWLEDGE_PATHS`; сканы положений требуют предварительного OCR.
Дополнительные документы получают источники `kb:*`; официальный оценщик учебного
набора использует только `rule:*` и `field:*`. Изменение обязательных требований
также требует согласовать детерминированную схему проверки с новой версией правил.

```powershell
.\.venv\Scripts\python.exe scripts/reindex_knowledge.py
```

В общие AI-логи записываются маршрут, имена полей, коды ошибок, источники и время.
Полный OCR, цитаты, значения полей и текст вопроса туда не записываются.
Сохранённые документы, поля и диагностические предложения модели — данные владельца;
они не заменяют общие обезличенные логи.

## Повторение измерений

```powershell
$dataset = 'C:\path\to\online-dean-participants-v1'
$env:LOCAL_AI_ENABLED = '1'
.\.venv\Scripts\python.exe scripts/benchmark_ai.py extraction --dataset $dataset
.\.venv\Scripts\python.exe scripts/benchmark_ai.py qa --dataset $dataset --force
.\.venv\Scripts\python.exe scripts/benchmark_ai.py evaluate --dataset $dataset
.\.venv\Scripts\python.exe scripts/stress_local_ai.py
```

Или `benchmark_ai.py all --dataset $dataset`. Извлечение проходит по всем PNG с
реальными OCR/CV: отдельный запуск Regex и отдельный запуск гибрида. QA использует
сохранённые гибридные поля; для двух чисто генеративных вариантов вопросы группируются
по 4 на документ, с одинаковыми источниками и лимитом 1024 токена. Время ответа
в сводке делится на 4; это амортизированное время, а не задержка одиночного запроса.
Для такого большого пакета при необходимости задайте `LOCAL_AI_TIMEOUT=180`.

Старой реализации Qwen в проекте не было. `qwen_baseline` — заново определённый
простой промпт, а не сохранённый исторический результат. `qwen_strict` использует
строгий промпт; оба варианта оцениваются по сырым ответам и не доступны пользователям.
`python_rag_qwen` использует маршрутизацию и программную проверку.

`reference_results.json` читается только стадией `evaluate`, после получения ответов.
Официальный оценщик запускается на сохранённых совместимых результатах.
Повторные запуски продолжаются по контрольным точкам; `--force` пересчитывает выбранную
стадию. Изменение хеша пайплайна/входного результата также отменяет переиспользование.

Проверки без модели:

```powershell
$env:LOCAL_AI_ENABLED = '0'
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
```

Браузерные проверки требуют `requirements-dev.txt` и установленного Chrome:
`tests/browser_local_ai.py`, `tests/browser_document_types.py`, `tests/browser_visuals.py`.

Результаты и ограничения измерений: [сводка](benchmarks/README.md). Полный сгенерированный отчёт находится локально в `benchmark_results/report.md`.
