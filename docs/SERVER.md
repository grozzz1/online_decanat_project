# Сервер, история переписки и Telegram Mini App

## Хранение

Используется только SQLite через SQLAlchemy Core. Таблицы, запросы и транзакции обслуживает SQLAlchemy; отдельный сервер базы данных не нужен. По умолчанию данные находятся в `private_data/`. Путь меняется через `DATA_DIR`.

| Файл или каталог | Содержимое |
|---|---|
| `decanat.sqlite3` | Пользователи, сообщения, обращения, имена вложений и пользовательские типы |
| `media/` | Исходные изображения и PDF |
| `local_ai/` | Индекс положений и параметры запущенной модели при заданном `DATA_DIR` |

Ключ пользователя — его числовой Telegram ID. Вход по одноразовой ссылке и вход Mini App открывают одну и ту же историю. Бот сохраняет входящие сообщения и свои ответы; сайт подгружает новые сообщения из SQLite при очередном опросе. Ответы деканата также сохраняются. После перезапуска история и обращения остаются; в обычном браузере потребуется новая ссылка для входа. Обработка, прерванная перезапуском, не отправляется в деканат повторно автоматически.

Вложения хранятся файлами, в базе — их имена, владелец и состояние. Лимит **1000 исходных вложений общий для всех студентов**, включая PDF. При добавлении следующего удаляется самый старый файл. Превью строятся из оригинала и не занимают дополнительные места. Сообщение и запись об удалённом вложении остаются в истории. При открытии такого фото сайт показывает причину удаления; HTTP API возвращает `410`. Чужие вложения недоступны.

SQLite работает в WAL-режиме. Для резервной копии остановите приложение и скопируйте весь `DATA_DIR`, включая файлы WAL, если они есть. Каталог данных не должен публиковаться через Nginx.

## Типы заявлений

Команды работают в группе с ID из `DEAN_CHAT_ID`:

| Команда | Действие |
|---|---|
| `/add_type Название заявления` | Добавить тип и выбрать «Сдача заявления», «Вопрос по заявлению» или оба раздела |
| `/types` | Показать стандартные и добавленные типы |
| `/remove_type` | Показать кнопки удаления добавленных типов |
| `/remove_type custom_…` | Удалить пользовательский тип по ключу |

Новый тип появляется в кнопках бота и в списке на сайте. Стандартные три типа удалить нельзя. Удаление пользовательского типа убирает его из нового выбора, сохраняя старые обращения.

Для пользовательских типов выполняются OCR и визуальный анализ. Вопросы обрабатываются по цитатам распознанного текста. Автоматические требования к обязательным полям для нового типа не задаются одним названием; интерфейс показывает, что такие правила ещё не настроены.

## Настройки

| Переменная | Значение |
|---|---|
| `DATA_DIR` | Каталог SQLite и вложений; локально `private_data` |
| `PUBLIC_BASE_URL` | Адрес сайта без пути: `http://IP` или `https://example.org` |
| `WEB_HOST`, `WEB_PORT` | Адрес и порт Waitress, по умолчанию `127.0.0.1:5000` |
| `FLASK_SECRET_KEY` | Постоянный ключ сессий; пусто — ключ сохраняется в SQLite |
| `TRUST_PROXY` | `1` за локальным Nginx; доверяется только прокси `127.0.0.1` |
| `ENV_FILE` | Файл окружения из переменной процесса; на сервере `/etc/online-decanat.env` |
| `LOCAL_AI_THREADS` | Число CPU-потоков модели, по умолчанию `2` |

Настройки Telegram, Tesseract и Qwen описаны в основном README. Файл `.env` с токеном в архив исходников не включается.

## Развёртывание

Установщик рассчитан на отдельный **Ubuntu 24.04 x64 VPS с systemd**, доступом `root` или `sudo`, портами 80/443 и доступом к PyPI, GitHub и Hugging Face. Проверка синтаксиса и конфигураций выполнена локально на Windows; полный запуск установщика на Ubuntu требует самого VPS.

Соберите архив на компьютере разработки:

```powershell
.\.venv\Scripts\python.exe scripts/package_deployment.py
```

Архив `.tmp/online-decanat-server.zip` содержит исходники и установщик. В нём нет виртуального окружения Windows, токенов, базы, переписки, вложений и весов модели.

Загрузите архив на сервер, распакуйте в отдельный каталог. При желании положите рядом с `main.py` свой `.env` с тремя настройками Telegram. Выполните из распакованного каталога:

```bash
sudo bash deploy/install.sh
```

При отсутствии обязательных значений установщик запросит токен, ID чатов и публичный адрес сервера. Домен можно добавить позже; сначала подойдёт `http://IP-сервера`.

Установщик устанавливает Python 3.12, Tesseract с языками и OSD, Nginx и зависимости; создаёт окружение, отдельного системного пользователя и службы. При `LOCAL_AI_ENABLED=1` также скачиваются Linux-бинарники llama.cpp и GGUF Qwen размером около 2,5 ГБ с проверкой SHA256. Службы включаются при загрузке сервера.

| Путь | Назначение |
|---|---|
| `/opt/online-decanat` | Код, окружение Python, llama.cpp и модель |
| `/etc/online-decanat.env` | Закрытая конфигурация |
| `/var/lib/online-decanat` | База, вложения и изменяемые данные |
| `/etc/nginx/sites-available/online-decanat` | Обратный прокси |

Для установки без модели заранее задайте `LOCAL_AI_ENABLED=0` в конфигурации. Уже скачанные веса можно положить в `/opt/online-decanat/models/` под именем из `scripts/setup_local_ai.py`; установщик проверит их контрольную сумму.

## Управление

```bash
sudo site start
sudo site stop
sudo site restart
sudo site status
sudo site logs
sudo site logs ai
sudo site logs all
sudo site doctor
sudo site config
```

`start`, `stop` и `restart` управляют ботом, сайтом и включённой моделью. `config` открывает настройки; после редактирования выполните `site restart`. `doctor` проверяет OCR, соединение с Telegram, доступность включённой модели и каталога данных без отправки сообщений.

Для обновления загрузите новые исходники в отдельный каталог и выполните:

```bash
sudo site update /путь/к/новым/исходникам
```

Данные и серверная конфигурация сохраняются.

## Домен и Mini App

Создайте DNS-запись домена на IP VPS. Затем выполните:

```bash
sudo site domain decanat.example.org admin@example.org
```

Команда настраивает сертификат через Certbot, HTTPS и `PUBLIC_BASE_URL`. Если HTTPS уже настроен другим способом:

```bash
sudo site url https://decanat.example.org
```

В BotFather откройте `/mybots` → выберите бота → **Bot Settings → Configure Mini App → Enable Mini App**. Адрес приложения: `https://decanat.example.org/miniapp`.

Для кнопки возле поля ввода вызовите `/setmenubutton`, выберите бота, задайте текст «Открыть деканат» и тот же адрес `https://decanat.example.org/miniapp`. После настройки HTTPS команда `/start` также показывает кнопку открытия личного кабинета внутри Telegram.

При каждом открытии `/miniapp` вход выполняется автоматически по свежему `Telegram.WebApp.initData`: сервер создаёт новую сессию для подтверждённого Telegram ID и заменяет старую. Код из бота вводить не нужно. Токен бота берётся из серверной конфигурации и никогда не передаётся браузеру. После смены `BOT_TOKEN` выполните `site restart`.

Сервер проверяет HMAC-подпись `initData`, срок действия и ID пользователя; `initDataUnsafe` для входа не используется. Для HTTPS Mini App предусмотрены защищённые partitioned cookie и разрешение встраивания страниц в Telegram Web. Обычный браузер сохраняет отдельный режим входа по одноразовой ссылке.

Протокол подписи: [Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app). Настройки встроенных cookie: [Flask](https://flask.palletsprojects.com/en/stable/config/#SESSION_COOKIE_PARTITIONED).
