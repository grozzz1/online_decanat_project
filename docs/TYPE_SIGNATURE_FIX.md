# Подтверждение типа и границы подписи — 15.10.2026

Историческая запись проверки до интеграции Qwen и очистки репозитория. Число тестов и времена ниже относятся к тому этапу. Текущие команды — в [README](../README.md), сводные измерения — в [benchmarks](benchmarks/README.md). Упомянутые `benchmark_results/...` остаются локальными генерируемыми файлами и не включены в Git.

При известном несовпадении типов жёлтая кнопка «Подтвердить выбранный тип» сразу
запускает отправку сохранённого файла. Синяя кнопка заблокирована до разрешения
расхождения. Сервер проверяет явное boolean-подтверждение, владельца, сессию, CSRF,
состояние обращения и наличие вопроса для соответствующего раздела. Выбранный тип
используется для извлечения полей, валидации и подписи отправленного документа.
Распознанный тип остаётся независимым; оба типа и `type_mismatch_confirmed=true`
сохраняются в обращении. Подтверждение типа не делает неполный документ корректным.

«Изменить тип» немедленно скрывает предупреждение и открывает существующий список
через `showPicker()` либо устанавливает фокус. Выбор не меняется автоматически,
файл сохраняется, исключённые типы в список не добавляются. Изменение выбора
проверяет сохранённые OCR/CV: совпадение открывает обычную отправку, другое
расхождение возвращает предупреждение. Если выбор не менялся, предупреждение
возвращается при следующей попытке отправить. Лишняя кнопка «Подтвердить тип» удалена.
Совпадающий и неизвестный типы отправляются обычным способом; для `unknown`
остаётся нейтральное сообщение без требования подтвердить расхождение.

Кнопки блокируются на время запроса и обработки; сервер допускает только один
переход обращения к отправке. После явного отказа Telegram доступен повтор того же
обращения. Полученные `message_id` и количество подтверждённых текстовых частей
сохраняются: уже доставленный файл/части повторно не пересылаются. После таймаута
с потерей ответа повтор блокируется: Bot API не даёт ключа идемпотентности,
а неизвестный результат нельзя безопасно считать отказом. Состояние находится
в памяти процесса и не переживает перезапуск сервера. Реальные сообщения при
разработке и проверках не отправлялись — транспорт заменён mock-объектами.

## Рамка подписи

Причина частичной рамки: контуры выделялись отдельно внутри узкой области OCR-ориентира
и в нижней части страницы. Обрезанный областью кандидат мог победить полную рамку
при дедупликации по уверенности. Малое морфологическое ядро также оставляло разрывы.

Теперь близкие штрихи объединяются дилатацией на полной странице до проверки
контекста; рамка вычисляется по исходным пикселям объединённых компонент и получает
небольшой относительный отступ. Размеры ядер и областей зависят от масштаба страницы
и OCR-текста. Длинные линии бланка удаляются с локальным восстановлением пересечений,
печатные слова и печати исключаются. OCR-фрагмент внутри пересекающего его длинного
нерегулярного штриха сохраняется. Отдельные регулярные символы не проходят проверку
связности. Явный «образец» и обрезание краем страницы не дают уверенной подписи студента.
Преобразование координат обратно к размеру оригинала сохранено; canvas использует
размеры страницы и текущий масштаб изображения.

Для `open-018` старая рамка `[440, 1222, 496, 1248]` заменена на
`[436, 1207, 622, 1251]`. Полная пустая линия и печатный ориентир остаются вне рамки.
Это пример результата, не настройка алгоритма на ID или координаты.

## Проверки и данные

- `python -m unittest discover -s tests -t . -q`: **74 теста прошли**.
  Новые проверки включают подтверждение исходного выбора, отказ без флага и
  некорректные значения флага, смену на правильный/другой неверный тип без OCR,
  неизвестный тип, повторный POST, отказ доставки и повтор без дублирования файла,
  таймаут, отдельные штрихи/выносные элементы, пустую линию, OCR внутри штриха,
  образец, обрезание страницей и координаты увеличенного изображения.
- `tests/browser_document_types.py`: Chrome проверил совпадение, расхождение,
  однократную отправку жёлтой кнопкой, сохранение выбора и файла, отсутствие
  автоматического добавления исключённого типа, возврат предупреждения без смены
  выбора, правильную/неправильную смену, `unknown`, ошибку и повтор.
- `tests/browser_visuals.py`: Chrome проверил четыре стороны рамки на canvas до
  и после увеличения и при узком экране, цвета, переключатель подсветки, страницы
  PDF и очистку старых рамок при выборе нового файла.
- Полный OCR/CV повторно выполнен на **30 исходных синтетических документах**
  набора в PNG и PDF. Это два представления одной выборки. PNG: **279/280** полей,
  PDF: **280/280**; классификация, комплектность и ответы на 120 вопросов в каждом
  представлении совпали с эталоном. Оставшаяся PNG-ошибка — латинское `OB-1009`
  вместо кириллического `ОБ-1009`. Метрики наличия подписей/печатей не ухудшились.
  Сравнение сохранённых рамок/статусов —
  `benchmark_results/signature_fix/bbox_comparison.json`.

Новые результаты: `benchmark_results/signature_fix/report.md`,
`benchmark_results/signature_fix/pdf_check/report.md`. Старые результаты
в корне `benchmark_results` сохранены для сравнения. Среднее время новых запусков
2.233 с / 2.373 с; два запуска выполнялись одновременно, поэтому сравнивать эти
времена с прежним последовательным запуском как ускорение/замедление нельзя.

Фрагмент из сообщения изучен визуально; отдельного исходного файла изображения
среди доступных вложений нет. Пиксельные проверки выполнены на документах набора
и контролируемых синтетических фикстурах. Набор не содержит эталонных bbox подписей:
IoU, полнота охвата штрихов и точность на реальных почерках **не измерены**.
Плотные соседние записи, курсивный печатный текст, штрихи поверх печатного текста,
перекрытие печатью и сильный шум остаются ограничениями эвристики. Подлинность не проверяется.
