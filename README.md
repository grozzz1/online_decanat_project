# Онлайн-деканат

Flask-приложение и Telegram-бот на Python 3.12. OCR выполняет локальный Tesseract,
поля извлекаются Regex, подписи/печати ищутся OpenCV. Внешние OCR/LLM API не используются.

## Установка и запуск на Windows

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe main.py
```

Все runtime-зависимости находятся в `requirements.txt`; зафиксированы версии,
проверенные в чистом окружении Python 3.12. `requirements-dev.txt` необязателен,
добавляет Playwright для браузерных проверок и ссылается на основной файл.
Из вариантов OpenCV нужен только `opencv-python-headless`: разные пакеты OpenCV
устанавливают один и тот же `cv2`, поэтому не смешивайте их в одном окружении.

Отдельно нужен исполняемый Tesseract с языками `rus`, `eng`, желательно `osd`.
Он не устанавливается Python-пакетом `pytesseract`. Настройки читаются из `.env`:

```dotenv
BOT_TOKEN=токен_бота
DEAN_CHAT_ID=ID_чата_деканата
ADMIN_LOG_CHAT_ID=ID_чата_журнала
TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe
```

Откройте http://localhost:5000 на компьютере запуска. Вход — по одноразовой ссылке
из `/start` Telegram-боту. Для бота необходим доступ Python к Telegram API.
Напрямую `webapp/app.py` запускать не нужно. История, сессии и документы пока
хранятся в памяти и теряются при перезапуске.

## Обработка и исправление типа

Локальные Qwen3-4B, гибридное извлечение, ответы по документам и BM25/RAG:
[установка, запуск и архитектура](LOCAL_AI.md). Дополнительные настройки без секретов —
[.env.ai.example](.env.ai.example). Сравнительный запуск:
`python scripts/benchmark_ai.py all --dataset <папка набора>`.

Изменения подтверждения типа и рамок подписи от 15.10.2026, список файлов,
74 автоматических теста и повторные измерения описаны в
[TYPE_SIGNATURE_FIX.md](TYPE_SIGNATURE_FIX.md). Сравнение рамки:
[до/после](benchmark_results/signature_fix/signature_before_after.png).

Поддерживаются JPG/PNG и PDF до 10 МБ, до 12 страниц PDF, до 20 мегапикселей изображения.
Общий пайплайн `utils/ocr.py` используется сайтом, ботом и бенчмарком.

- Название/тип определяются по OCR-заголовку и содержимому, включая координатный OCR.
  Выбор пользователя сохраняется отдельно и не используется как результат классификации.
- При известном фактическом типе поля извлекаются по его схеме. При `unknown`
  используется выбранная схема с явным предупреждением о неопределённости типа.
- В «Отправить заявление» доступны академический отпуск и справка о практике.
  Справка об обучении сохраняется в общем справочнике, backend, боте и разделе
  «Вопрос по заявлению».
- При известном несовпадении сайт сохраняет файл и приостанавливает пересылку.
  Жёлтая кнопка «Подтвердить выбранный тип» сразу отправляет документ с выбранным
  пользователем типом. Сервер сохраняет `selected_document_type`, `detected_document_type`
  и `type_mismatch_confirmed=true`, повторно проверяет поля по выбранной схеме.
  Замечания к комплектности не исчезают из-за подтверждения типа.
- «Изменить тип» скрывает предупреждение и открывает существующий список без подмены
  выбора и добавления запрещённых вариантов. Изменение выбора повторно проверяет
  сохранённые OCR/CV без распознавания файла; при совпадении доступна синяя кнопка
  «Подтвердить и отправить». Другой неверный выбор возвращает предупреждение.
  Если выбор не менялся, предупреждение возвращается при следующей попытке отправки.
- Совпадение типов не создаёт предупреждение: исходное нажатие «Отправить» остаётся
  подтверждением обычной отправки. Неизвестный тип сопровождается нейтральным сообщением
  и также отправляется без подтверждения расхождения.

Повторные нажатия блокируются на клиенте и сервере. После явного отказа Telegram
можно повторить отправку сохранённого обращения: уже подтверждённые части не дублируются.
При потере сетевого ответа результат отправки неизвестен, поэтому автоматический повтор
блокируется до проверки получения в деканате. Состояние доставки, как и остальные обращения,
хранится в памяти процесса; перезапуск сервера его сбрасывает.

Исходные маршруты сохранены, добавлены защищённые POST:
`/api/requests/<id>/type`, `/api/requests/<id>/confirm`.
Проверяются сессия, владелец документа, CSRF и состояние обращения.

Внутренний результат содержит `selected_document_type`, `document_title`,
`detected_document_type`, `document_type_matches_selection`, `ocr_text`, `fields`,
`extraction`, `visuals`, `validation`. В пользовательские логи OCR-текст не записывается.
Отчёт логирования содержит источник, типы, заголовок, статусы и счётчики полей.
`found` означает извлечённый кандидат, а не сверку с эталоном: точность измеряется отдельно.
Проверки комплектности основаны только на выданном вымышленном [rules.md](rules.md).
Окончательное решение остаётся за сотрудником деканата; юридическая подлинность не проверяется.

## Бенчмарк

Путь к набору должен содержать `documents.zip`, `documents.json`, `questions.json`,
`reference_results.json`, `evaluate.py`. Извлечение и оценка — разные команды:

```powershell
.\.venv\Scripts\python.exe scripts/benchmark.py run --dataset "C:\Users\timof\Downloads\online-dean-participants-v1"
.\.venv\Scripts\python.exe scripts/benchmark.py report --reference "C:\Users\timof\Downloads\online-dean-participants-v1\reference_results.json" --evaluate "C:\Users\timof\Downloads\online-dean-participants-v1\evaluate.py"
```

`run` читает изображения непосредственно из ZIP и не читает эталоны. Оно сохраняет
OCR, внутренние результаты, время и `results.json` официального формата.
`report` сравнивает уже сохранённые значения и запускает неизменённый официальный evaluator.
В `benchmark_results`: `summary.csv`, `field_accuracy.csv`, `document_results.csv`,
`errors.csv`, `report.md`, `official_evaluation.json`, `processing.log`, `raw/`.

Для проверки альтернативных PDF-представлений тех же 30 документов:

```powershell
.\.venv\Scripts\python.exe scripts/benchmark.py run --dataset "C:\Users\timof\Downloads\online-dean-participants-v1" --representation pdf --output benchmark_results/pdf_check
.\.venv\Scripts\python.exe scripts/benchmark.py report --reference "C:\Users\timof\Downloads\online-dean-participants-v1\reference_results.json" --evaluate "C:\Users\timof\Downloads\online-dean-participants-v1\evaluate.py" --output benchmark_results/pdf_check
```

30 PNG и 30 PDF — **30 уникальных документов**, а не 60 независимых примеров.
Набор использован при разработке, поэтому измерения не являются независимой проверкой.
Макро-точность полей соответствует официальной метрике: среднее внутри документа,
затем по документам. Микро-точность считается по всем 280 значениям.
Количество присутствующих полей (например 9/10) не является accuracy.

Официальная схема требует `signature_present`/`seal_present` с boolean и строку
`не найдено` для пропусков. Внутри приложения неизвестные значения сохраняются `null`.
Для официального экспорта unknown-отметка консервативно превращается в `false`,
но исходный unknown и его количество остаются в JSON/CSV. Результаты не подставляются
из эталонов и не привязаны к ID документа. Свободные ответы для evaluator формируются
локальным кодом только из полей и пунктов Положения, не языковой моделью.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:PYTHONPATH = "$PWD"
.\.venv\Scripts\python.exe tests/browser_visuals.py
.\.venv\Scripts\python.exe tests/browser_document_types.py
```

Для браузерных проверок нужен установленный Google Chrome. Они используют реальный Flask,
но подменяют Tesseract и Telegram-транспорт. Реальные сообщения в Telegram не отправляются.
Отдельный измеряемый бенчмарк использует настоящий Tesseract и исходные изображения.
В [DOCUMENT_FIELDS.md](DOCUMENT_FIELDS.md) и [DOCUMENT_CV.md](DOCUMENT_CV.md) — детали модулей;
в `benchmark_results/report.md` — фактические измерения и ограничения.

## Ограничения

Классический CV не проверяет подлинность и может ошибаться на другом оформлении,
бледных/перекрывающихся отметках. Regex не понимает произвольные формулировки.
Tesseract может путать кириллицу и латиницу в номерах; без надёжного основания
они не заменяются по эталону. Восстановление перспективы и OCR рукописных полей не реализованы.
Предоставленные синтетические документы не доказывают качество на реальных снимках.
